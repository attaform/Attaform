# Phase-1 analyst digest (14 subsystem/cross-cutting reports)

## validation-display

HEADLINE: The 3-channel error model is really 2 stores plus a derivable set; collapsing to one tagged store, DEV-gating error prose, and deduplicating process-form's three validation shells cuts ~1.2 kB gz and removes the biggest per-keystroke allocation churn in the read path.
FAT: Direct footprint: process-form 1566 gz, errors 852, error-codes 136, display-state 330, display-engine 333 = 3.2 kB gz. But the real weight of the 3-channel model is threaded elsewhere: every merged read re-implements the schema→blank→user concatenation with per-channel visibility rules — getErrorsForPath (create-form-store.ts:3270), buildLeafFieldStateBase (field-state-api.ts:179-196), aggregateErrorsAt (field-state-api.ts:814-816), errors-proxy resolveLeaf/enumeration/materializeErrors (errors-proxy.ts:82-87, 215-217, 353-355), build-form-api valid computed (630-632), plus dual writer families (setAll/setForPath/clear × 2) and dual history/hydration snapshot fields. That's 6+ read sites × 3 maps each, easily ~1.5 kB raw of pure channel-threading.

errors.ts is anomalously string-dense: 852 gz from only 1890 raw (45% vs the 31% norm) because four misuse-error constructors carry ~950 chars of tutorial prose (InvalidUseFormConfigError, RegistryNotInstalledError, OutsideSetupError, ReservedFormKeyError) that ships in prod for errors thrown only on developer misuse.

process-form has three parallel validation shells: the reactive validate()'s kickoff (lines 134-179) duplicates the increment/decrement + adapter-throw try/catch + composeWithDerivedBlank that runImperativeValidation (242-280) already centralizes for validateAsync/parse; the catch-block throw-grouping (653-662) duplicates applySchemaErrorsForSubtree's group-by-canonical-key. handleSubmit itself (451-697) is dense but semantically load-bearing (generation guards, transform drain, entry-clear) — little collapsible there.

The display engine (663 gz combined) is genuinely minimal and well-designed: one timer, one tick ref, no per-field watchers. Only trims: test-only introspection methods and two-file module glue.
IDEAL: One error store, tagged entries. `errors: Map<PathKey, ValidationError[]>` where each entry carries `src: 0|1` (schema|user; 1 bit, minifies to a property check). Blank is never stored: it is fully derivable from `blankPaths.has(key) && schema.isRequiredAtPath(segments)` — exactly what the per-leaf path already does (field-state-api.ts:190) after the P3 perf fix proved the derived Map was a liability. Delete the derivedBlankErrors computed and collectScopedBlankErrors; aggregate readers iterate blankPaths directly.

One writer, one reader. Writers become `writeErrors(src, scope, entries)` / `clearErrors(src, scope?)` — clear-by-tag is a filter pass (writes are cold; reads are hot). One shared iterator `forEachError(prefix, cb(entry, segs, active))` that applies the active-path filter for src=schema and passes user entries through, replacing the 6 hand-rolled merge loops in errors-proxy, field-state-api, build-form-api, and the store. History snapshots one map; hydration replays one array.

process-form at ~60% of its bytes: runImperativeValidation stays the single validation shell; the reactive validate() becomes a ~20-line wrapper (watchEffect → queueMicrotask → runImperativeValidation → write ref), sharing adapterThrowResponse. validateAsync and parse unify into one `parse(path?, {commit?})`; ValidationResponseWithoutValue and stripData disappear. The submit handler keeps its exact semantics but reuses a shared groupByCanonicalKey (also used by applySchemaErrorsForSubtree). applyInvalidSubmitPolicy + the store's getFirstErrorElement/rebuildSortedRegistrations move to a lazily-imported focus module awaited inside the already-async submit handler.

ValidationError slims to { message, path, code?, data? }: formKey is dropped per-entry (the wizard already fallback-stamps at aggregation, use-wizard.ts:596, and within a form it is a constant). Prod error messages become `attaform:E<code> <docs-url>`; the prose survives only under **DEV** (Vue's own pattern), keeping error-codes.ts as the stable branchable surface.

display-state + display-engine merge into one ~650 gz module unchanged in behavior; size/has/hasTimer test hooks go behind **DEV** or a test-only export.

What disappears: derivedBlankErrors computed, one Map + one writer family, 5 duplicated merge loops, kickoff's duplicate shell, stripData/one response type, per-entry formKey, ~950 chars of prod prose, dual history error snapshot fields. Result: same feature surface, ~1.9-2.1 kB gz for what is ~3.2 direct + ~1 threaded today.
PERF: Biggest win is structural, not byte-driven: derivedBlankErrors (create-form-store.ts:1551) rebuilds a fresh Map on ANY blank transition, invalidating every aggregate reader (aggregateErrorsAt, errors-proxy enumeration/materialize, build-form-api valid) at once — the leaf path was already carved out for exactly this (P3, field-state-api.ts:181-190); deleting the computed extends that fix to aggregates. aggregateErrorsAt allocates a buckets Map + array spreads + sort + flatMap per read and re-runs on every error-store mutation (i.e. every keystroke that validates) per subscribed container — inserting into an ordinal-sorted array would remove the sort+flatMap. replaceErrorsIn (3151) does clear()+set-per-key, firing full collection invalidation on every whole-form validation pass; a keys-diff (delete-missing, set-in-place) like applySchemaErrorsForSubtree already does would cut trigger fan-out. Each reactive validate() call allocates a watchEffect + ref + closure trio and schedules a microtask on every form mutation for the form's lifetime — fine as opt-in, but worth documenting as per-call cost. The display engine is a perf model to preserve: one timer, one tick ref, machines map bounded by non-idle fields, zero per-field watchers. Tagged-store merge makes reads one map lookup instead of three per path per recompute.
FINDINGS:

## arrays-history

HEADLINE: Move history to an attaform/history subpath plugin (~1.3 kB gz off eager, incl. its private diff-apply/path-walker helpers) and collapse the four-way-duplicated array permutation machinery into one ~1.1 kB module, for a combined ~1.9-2.4 kB gz eager cut with better keystroke perf.
FAT: Subsystem eager total is ~2,858 gz: history.ts 1127, array-identity 503, array-state-migrate 486, array-bookkeeping 428, field-arrays 314. History is 40% of the subsystem and fully opt-in (use-abstract-form.ts:274 only instantiates it when merged.history is set) yet statically imported (use-abstract-form.ts:22), and it is the SOLE consumer of applyPatchesForward/applyPatchesInverse (diff-apply.ts:425/456) and, transitively, of deleteAtPath/deleteAtPathOffset (path-walker.ts:265-301), so its true eager cost is ~1.35 kB. Inside history, roughly half the bytes are the delta model: Delta type plumbing, applyDeltaForward/Inverse, errorsEqual/errorFieldsEqual/dataEqual (~60 lines of deep compare), diffBlankPaths, and the base-folding cap loop, all existing to bound memory that a plain snapshot ring would bound more simply, since captureSnapshot() already deep-clones the entire form on every change anyway (history.ts:295).

The array side's fat is quadruplicated permutation logic over the same five op kinds: remapForOp's switch (array-state-migrate.ts:31), applyOp's switch (array-identity.ts:112), variant-memory's applyArrayOp switch (variant-memory.ts:84, whose clear-set is exactly changedIndices(remap)), and freshElementIndices' switch (create-form-store.ts:1135, which is exactly remap.fresh). On top of that there are three near-identical snapshot/delete/re-set relocation walkers: migrateMapSubtree, migrateSetSubtree, and applyRemap's private relocate() (array-identity.ts:145-177), which even comments that it mirrors migrateMapSubtree while tokens/baselines are literally Map&lt;PathKey, string[]&gt; and could be migrated by it. field-arrays.ts is already lean and mostly irreducible; array-bookkeeping is largely a deps-destructure plus a tuple of migrate calls and two structurally identical key-scan loops (dropSchemaErrorsAtChangedIndices, abortValidationAtVacatedIndices).
IDEAL: Two modules replace five.

1. src/runtime/core/arrays.ts (~1.0-1.1 kB gz, eager). One factory createArrayEngine(deps) owning tokens, baselines, and all relocation. Data structures: tokens: Map&lt;PathKey, string[]&gt;, baselines: Map&lt;PathKey, string[]&gt;, one monotonic counter. Core primitives: (a) remapForOp(op, oldLen) -&gt; {moved, vacated, fresh} — the single op switch in the codebase; (b) relocateKeys(entries, del, set, rewrite?) — one generic snapshot/delete/re-set walker used for fields, userErrors, originals, the three Sets (via delete/add adapters), the two validation maps, AND tokens/baselines (killing applyRemap's private clone and migrateSetSubtree); (c) permuteList(ids, remap) — tokens follow the remap (newIds[to]=old[from], allocate for fresh), killing applyOp's switch; (d) one scanKeysAtIndex(store, arrayPath, predicate, action) shared by dropSchemaErrorsAtChangedIndices and abortValidationAtVacatedIndices. tokenAt/realign/hasStructuralChangeUnder/rebaselineAll keep their current logic (~40 lines). The write funnel computes remap ONCE at the top of the arrayOp branch and threads it: variantMemory takes changedIndices(remap) instead of its own switch; the four freshElementIndices call sites read remap.fresh. field-arrays.ts helpers fold in as a buildFieldArrayApi export of the same module (their bodies are already minimal). What disappears: array-identity.ts, array-state-migrate.ts, array-bookkeeping.ts, field-arrays.ts, variant-memory's applyArrayOp switch, freshElementIndices.

2. attaform/history subpath entry (~0.5 kB gz, never eager). Public API: historyPlugin(config?) returning (store: FormStore) =&gt; HistoryModule; useForm({ history: historyPlugin({ max: 128 }) }). use-abstract-form keeps only the ~6-line wiring (call if function, cache on state.modules, registerCleanup). Internals rewritten as a snapshot ring: positions: HistorySnapshot[] ring buffer + cursor; every onFormChange pushes captureSnapshot() (already O(form) today); undo/redo move the cursor and call restoreCurrent. Deletes Delta, applyDeltaForward/Inverse, applyPatchesForward/Inverse, errorsEqual/dataEqual/errorFieldsEqual, diffBlankPaths, the base-fold loop — and frees diff-apply's patch appliers plus path-walker's deleteAtPath from every bundle without history. Memory: max × form-clone, fine at forms' KB scale; drop the default cap from 128 to ~50 if desired.

Net subsystem: ~2,858 gz eager -&gt; ~1,050-1,150 eager + ~500 lazy, with fewer per-keystroke allocations in both halves.
PERF: History enabled = O(form) deep clone (structuralSnapshot) + full diffAndApply + captureErrorEntries copy + errorsEqual deep-compare on EVERY form change (history.ts:277-318), plus O(n) array respreads of undoDeltas/redoDeltas per keystroke (n up to 127). The snapshot-ring rewrite keeps the clone but deletes the diff, error compares, and respreads: strictly fewer allocations per keystroke. Array ops: migrateElementState runs 9 full-store scans, each decoding segmentsForPathKey per key (array-bookkeeping.ts:162-203), plus two more scans in dropSchemaErrors/abortValidation and two in applyRemap, so one swap is ~13 full iterations over all path-keyed state with string parsing per entry. A merged engine can do one scan per store max, and cheaper: match on the canonical PathKey string prefix before decoding segments. tokenAt correctly reads length off toRaw(form) to avoid coupling every element rollup to array length (create-form-store.ts:1356-1369): preserve that invariant in any rewrite. seedFreshElement invokes the full diffAndApply walker just to enumerate leaves of one element (array-bookkeeping.ts:208): a trivial leaf walk would be smaller and allocation-free. changedIndices allocates three collections per op even for append (empty remap): early-out for the append fast path.
FINDINGS:

## form-api-proxies

HEADLINE: This subsystem is ~9.3 kB gz of the 45.4 kB eager set, and roughly half of it is compensating machinery for two self-inflicted design choices: callable function-target proxies (which break JSON/keys/coercion/Array.isArray and require ~3.2 kB gz of traps to repair) and hand-enumerated 30-key mirror objects written four times over.
FAT: Subsystem eager total ≈ 9.35 kB gz: build-form-api 2755, field-state-api 1828, surface-proxy 1260, use-abstract-form 1089, field-state-proxy 602, errors-proxy 594, field-arrays 314, callable-readonly-snapshot-proxy 252, values-proxy 218, proxy-live-keys 151, proxy-readonly-helpers 119, field-ids 108, field-meta(+store) 61. The fat concentrates in three patterns. (1) The callable-proxy compensation stack: making `form.values`/`form.fields`/`form.errors` typeof-function so `form.errors(path)` works forces function Proxy targets, which then need toJSON/toString/valueOf/Symbol.toPrimitive quartets (proxy-readonly-helpers), Array-target swapping + `length` invariant handling for renderList (surface-proxy.ts:365-370, 591-613), sucrase `.call/.apply/.bind` downlevel shims (surface-proxy.ts:221-244, 526-528), Vue sigil short-circuits, schema-authority collision resolution for `toString`/`hasOwnProperty`, and per-surface materializers rebuilt on every stringify (materializeErrors + placeAt ≈ half of errors-proxy; materializeFields in field-state-proxy). (2) Hand-written key mirrors: the same ~30 FieldState keys are enumerated five times — FIELD_STATE_KEYS set (field-state-proxy.ts:33-71), getFormMetaBase getter forest (build-form-api.ts:174-293), formMeta getter forest (build-form-api.ts:711-876), and the two return literals in buildLeafFieldStateBase / buildContainerFieldStateBase (field-state-api.ts:228-262, 591-630). (3) exactOptionalPropertyTypes ceremony: ~30 conditional-spread expressions across mergeWithDefaults, buildFreshState's createOptions, trichotomyOverride, and build-form-api's apiOptions/registerConfig blocks. use-form.ts itself is thin (guard + adapter wrap); the double-composable cost is mostly type-level, not bytes.
IDEAL: Target ≈ 4.5 kB gz for the same features. Modules: create-form-api.ts (~1.6 kB gz), field-state.ts (~1.2), fields-tree.ts (~0.4), errors-tree.ts (~0.3), field-arrays.ts (0.3, unchanged), use-form.ts per adapter entry (~0.5), field-ids/meta (~0.2). What changes: (a) `form.values` becomes Vue's own `readonly(state.form)` proxy exposed through a computed — deletes values-proxy, callable-readonly-snapshot-proxy, proxy-readonly-helpers entirely; native Array.isArray, enumeration, JSON, write-blocking all come from Vue. Dynamic reads move to `form.value(path)` (a 3-line getAtPath wrapper). (b) `form.errors` becomes a memoized `computed` that builds the sparse plain error tree once per error-store change (today's materializeErrors, run once instead of per-stringify) — dot access is then plain object reads on real data, zero traps; `form.errors(path)` survives as the separate function it already is internally (`aggregateErrorsAt`). The `''` container-self sentinel and unknown-server-key behavior are properties of the tree builder, kept. (c) `form.fields` keeps lazy dot-drill via ONE ~90-line proxy: get → descend (cached child) or FieldState terminal backed by the existing per-path computed; ownKeys from live value; toJSON only. No callable root, no coercion quartet, no transpiler shims, no schema-authority arbitration (schema fields named `toString`/`hasOwnProperty`/`call` become documented-unsupported); `form.field(path)` is the call-form. (d) One exported FIELD_STATE_KEYS list drives everything: fields-tree leaf keys, `form.meta` built by a defineProperty loop over `rootFieldState.value[k]`, the predicate's FormMetaBase, and snapshot loops — the four getter forests disappear. (e) FieldState assembly is one builder where a leaf is the degenerate container (zero walked descendants + own record), with an O(1) leaf fast-path for errors. ## defensive-code

HEADLINE: Defensive/wrong-layer code in runtime/core is worth ~1.8 kB gz eager (4%) and meaningful per-keystroke perf, but the real defensive tax is architectural: every write re-canonicalizes and re-verifies the same path through 5+ independent path-keyed cache lookups instead of trusting one rim-canonicalized handle.
FAT: The bytes in this subsystem are NOT primarily in try/catch wrappers (41 sites, mostly legitimate consumer-callback isolation per the no-uncaught-exceptions policy, ~30-60 raw bytes each). The defensive fat concentrates in four places. (1) Eager diagnostic prose: errors.ts is 852 gz at a 0.45 gz/raw ratio because it is mostly English guidance strings (InvalidUseFormConfigError, RegistryNotInstalledError, etc. each carry 2-4 sentences plus URLs), and create-form-store ships unconditional prod console.error invariant messages ("This is a bug in the construction pipeline", create-form-store.ts:4044,4078) that re-verify what the construction pipeline guarantees. (2) Path re-canonicalization at every layer: canonicalizePath appears 36 times in create-form-store alone, 80+ across core; paths.ts (698 gz) carries TWO bounded FIFO caches plus a JSON.parse inverse-recovery path (segmentsForPathKey, coerceToPathKey) that exist only because PathKeys are stored keyless and segments must be recovered later — a self-inflicted wound; keyForSegments (array branch, the hot one) is uncached and does Array.from+map+JSON.stringify+Map-write per call. (3) Paranoid value hygiene: stripSymbolsDeep deep-walks and shadow-allocates EVERY written container (create-form-store.ts:1072, its "zero allocation" comment is false — `out` is built unconditionally), defending against symbol-keyed consumer writes whose stated justification (persistence JSON) is stale post persist-removal. (4) Below-rim re-validation: useForm and useAbstractForm run the identical `schema === undefined` check and throw the same error; normalizeNumericOption is a 5-field config-object ceremony for clamping three numbers; hydration re-verifies 8 fields per record structurally when a single payload version stamp would catch the rolling-deploy case. Two modules (assertions.ts, extract-schema-fields.ts) have zero importers — dead source shipped in the tarball.
IDEAL: Trust-boundary architecture: validate once at the rim, raw trusted core.

Module layout: (a) `rim.ts` — the only layer that sees consumer input. It canonicalizes every path into a PathRef `{segments, key}` exactly once, disambiguates call forms, normalizes options (one `clamp(v, def)` for numerics), normalizes error inputs, and wraps every consumer callback through ONE shared `guard(label, fn)` helper implementing the no-uncaught-exceptions policy (replaces ~10 hand-rolled try/catch+console.error loops). (b) `core/` functions take PathRef and trusted typed args — required params, no option re-checks, no defensive typeof/undefined guards below the rim, no try/catch except where a consumer callback or adapter crosses back in (already funneled through guard). (c) `diag.ts` — all warn/error prose lives behind `__DEV__`; prod throws `AttaformError(code)` with a docs URL pattern (`attaform.dev/e/CODE`), the Vue/React error-code model. Unconditional prod invariant console.errors become `__DEV__` asserts that compile out.

Data structures: PathKey machinery shrinks to `parseDotted` + one string-keyed memo. The inverse cache, segmentsForPathKey, coerceToPathKey, pathKeyToDotted all disappear because PathRef travels with both representations and every store record that needs segments already stores them (FieldRecord.path, OriginalsRecord.segments). isPathKeyUnder becomes isPathPrefix on stored segments.

Second structure: a resolved SchemaNode record per path — `{slimKinds, isPreprocessLeaf, du, required, emptyValue}` — minted once per PathKey in one cache, replacing the five separate path-keyed caches in abstract-schema-factory that each re-canonicalize on lookup. The write path becomes: one node lookup, then straight-line checks. Store-creation-time capability flags (`hasDU`, `hasCoercion`, `hasTransforms`) skip whole write-pipeline stages for the 95% of forms that never use them — the cross-variant ancestor loop, DU Case A/B reshape probing, and du-stubs walk simply don't run.

What disappears: assertions.ts, extract-schema-fields.ts (dead); stripSymbolsDeep (dev-only warn instead); deep hydration shape guards (payload version stamp + one try/catch); the duplicated rim check in useForm/useAbstractForm; resolveTrichotomy, normalizeNumericOption, cast-only wrappers (validate/validateAsync/parse re-wrap closures in build-form-api) — folded inline. Net: ~1.8-2 kB gz eager off this subsystem, and a keystroke write drops from ~8 path serializations + 2 deep walks to 1 lookup + the diff walk.
PERF: Per-keystroke leaf write today: rim canonicalizePath (cached) → stripSymbolsDeep → 2 schema-cache lookups in the slim gate → up-to-2×depth+2 getUnionDiscriminatorAtPath memo lookups, each minting a JSON.stringify key via uncached keyForSegments (Array.from + map + stringify + a Map write into the inverse cache) on a freshly path.slice()'d array → another canonicalizePath for blank bookkeeping → walkAuthoredFromConstraints → mergeStructural → diffAndApply. The blank-path descendant sweep is correctly gated on container pre-values (good), but isPathKeyUnder re-derives segments from JSON keys via the inverse cache instead of using stored segments. Fixes with the largest perf yield: capability flags (hasDU) skipping the union machinery, PathRef threading (kills keyForSegments churn plus the per-canonicalization inverse-cache Map write), one SchemaNode lookup per write, and stripSymbolsDeep removal. The rim cast-wrappers (validate/validateAsync/parse re-wrap closures) add 3 closures per form instance — trivial individually, but the same per-form closure pattern is the store's structural problem (finding 8 of ground truth).
