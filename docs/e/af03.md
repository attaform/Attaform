# AF03

**Retired. Nothing emits this code any more.**

You are most likely here from a message printed by an older build. The page stays because that message stays in the wild.

## What it used to mean

At `useForm(...)` the adapter walked every node in your schema and checked its kind against a list. Known-good kinds passed, known-bad kinds raised [AF02](/e/af02), and AF03 was the third bucket: a kind outside both lists. In practice that meant your installed Zod was newer than the list the Attaform version shipped.

That is the part worth spelling out, because it made the audit a scheduled failure rather than a safety net. The day Zod shipped a new kind, anyone who used it got a crash at mount from Attaform, for a schema Zod itself parsed perfectly well. The fix on offer was to wait for an Attaform release.

## What happens now

The audit is gone entirely. A kind Attaform has no specific handling for is carried opaquely: no blank is derived for it, the write gate stays permissive, and it exposes no sub-paths. The schema's own `parse` is what decides whether the value was legal, which is the right authority for it. A schema a newer Zod can parse is a schema Attaform can mount.

[The schema contract](/docs/schemas/contract#what-the-adapters-accept) covers what Attaform asks of a schema and how the adapters read it.

## If you saw this from an older build

Upgrade Attaform. The kind that tripped the audit will mount as written.
